## Findings
1. `tests/` (no file): the shutdown-timeout branch of `ConversionJobQueue.DisposeAsync` (`src/WheelConvert.Core/Jobs/ConversionJobQueue.cs:204-210`) has no test. In a scratch run I removed `.WaitAsync(ShutdownGrace)` entirely (dispose would hang forever on a stuck converter) and all 69 Core tests still passed. Why it matters: the PR claims "same behaviour"; a regression here would make app exit hang. Fix (follow-up WP, since the test project is not in WP-22's Owns): add a test with a fake converter that ignores cancellation and assert `DisposeAsync` returns within ~6 s.
2. `src/WheelConvert.Core/Jobs/ConversionJobQueue.cs:211`: `catch (Exception ex) when (ex is not OperationCanceledException)` lets a Canceled worker task escape `DisposeAsync` and skip disposing the token sources. The old `WhenAny` code continued silently in that case. In practice it is unreachable (`RunOneAsync` and `Raise` catch everything, workers use no token), so non-blocking. Fix (optional): catch all exceptions there, or drop the filter.
3. `docs/modules/WP-22-release-hardening.md:30` (acceptance 4): result is "PARTIAL", not one of PASS / FAIL / NEEDS USER. CA2027 is not raised by any .NET 8 analyzer on this machine or in CI, so the test as written can't show anything. Fix: mark it NEEDS USER (or "not testable on .NET 8 SDK"), with the reading-based reason already given.
4. `docs/modules/WP-22-release-hardening.md:29` (acceptance 3): the actual PR artifact's ProductVersion is `0.0.0-pr23+<commit>`, not `0.0.0-pr23` as the table expects. The tray strips `+commit`, but Explorer's Properties > Details will show the suffix on released exes. Non-blocking; acceptance 6 (user) should expect `0.1.0-rc2+<commit>` in Properties, or a follow-up can set `IncludeSourceRevisionInInformationalVersion=false` in `release.yml`.
