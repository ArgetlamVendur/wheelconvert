## Findings
1. **Merge blocker, docs-only: `docs/STATUS.md` conflicts with `main`.** PR #27 (`a44703e`) landed on `main` just before this PR was opened and rewrote rows 13, 21, 22; this PR edits row 14 on the old base `a695592`, so Git reports adjacent-line conflicts (`docs/STATUS.md:19-20`). Fix: the builder (or orchestrator) merges/rebases on `main` and keeps both: `main`'s rows 13/21/22 plus this PR's row 14. No code change is needed; whoever merges should confirm the resolution commit touches only `docs/STATUS.md` (AGENTS §7).
2. Non-blocking: a locked or unreadable input is reported as an output error. `PdfSource.TryOpen` lets `IOException` / `UnauthorizedAccessException` from opening an input escape (`PdfSource.cs:30`), and `PdfMerger.cs:83-85` maps those to `OutputFailed` "Couldn't save the file here." That's the wrong message when, for example, one of the PDFs is open exclusively in another app. Same mapping as the existing single-file paths (`PdfConverter.cs:109`), so it isn't new behaviour. `InvalidOperationException` thrown by PDFsharp while importing pages would get the same message. Follow-up: catch open failures per input and return a message that names the file (for example "Couldn't open <name>. Is it open in another app?").
3. Non-blocking: page-level cancellation (`PdfMerger.cs:66`) has no test. Acc 5 cancels on the first progress report (after file 1 of 3), so removing only the per-page check still passes. The builder disclosed this. Follow-up: a test with a token that cancels from a page-count hook, or per-page progress.
4. Non-blocking: the zero-page rule (`PdfMerger.cs:59-62`) has no test (mutation 12). It isn't a WP requirement, and PDFsharp may not be able to write a valid zero-page file for a fixture. Follow-up: add a test if a fixture can be made.
5. Non-blocking: messages that include the file name (`PdfMerger.cs:47,53-54,61`) can go past the 120-character limit (AGENTS §6) when names are very long. Follow-up: shorten long names the same way across converters.
6. Non-blocking, spec gap the builder already disclosed: Gotchas asks for a README note (bookmarks/metadata dropped; same-name form fields may clash), but README isn't in this WP's Owns list. Follow-up for the orchestrator/user: add the note in a docs PR.
