## Findings (all non-blocking)

1. **Non-blocking: `AnimatedGif_OnlyFirstFrameBecomesOnePage` passes without the first-frame settings.**
   `ImagesToPdfTests.cs` (new GIF test) still passes when `FrameIndex = 0, FrameCount = 1` is removed from `ImagesToPdf.cs:156` (mutation FRAME). `new MagickImage(path, ...)` already keeps only the first frame, so the settings are a belt-and-braces guard and the test checks the behaviour, not the line. That is acceptable. The test still guards the requirement "one page per multi-frame file".
   Fix: none needed. Optionally add a comment on the test saying it checks the behaviour, since `MagickImage` reads one frame anyway.

2. **Non-blocking: the new `AddPage` catch is not covered by a test.**
   `ImagesToPdf.cs:136`. Narrowing the filter so it never matches (mutation ADDPAGECATCH) still passes. It is hard to make PDFsharp reject an image that Magick has just re-encoded, so this is reasonable to leave untested. The filter `when (ex is not OperationCanceledException)` is correct. No cancellation token is used inside that `try` anyway, so `OperationCanceledException` can't be swallowed there. One small point: the catch also turns `OutOfMemoryException` into "Couldn't read <name>.". For a one-page image that is acceptable, and it is better than the earlier misleading "Couldn't save".
   Fix: none required. Follow-up: consider `when (ex is not (OperationCanceledException or OutOfMemoryException))`.

3. **Observation: scope of the path scrubbing.**
   `LogFailure` scrubs only the paths the converter knows: every source and the temp file, after `Path.GetFullPath`, in both separator forms, ignoring case. That covers how Magick.NET prints a path on Windows (as it was passed in, which is the full path from the request). It would not catch a path Magick builds itself, such as its own `%TEMP%\magick-*` files for delegates, or 8.3 short names. Those are out of scope, and Magick doesn't print them for the formats used here. The scrub is reasonable and matches `ImageConverter.LogFailure`. `GetFullPath` can throw on odd input, but it runs inside the `try`, so it would only cost the log line and never the result.
