## Findings (none blocking)
1. `docs/modules/WP-16-smaller-images-video.md:39` — Row 3 says "PASS for AVIF". The test asks for a HEIC sample, and no HEIC file was decoded. HEIC goes through a different decoder (libheif + libde265) than AVIF, so AVIF only proves the shared part (extension mapping, resize, JPEG settings). Same situation as WP-06 test 7, which stayed NEEDS USER. **Fix:** make the cell start with `NEEDS USER` (e.g. "NEEDS USER: real HEIC from a phone; AVIF sample PASS, same code after decode"), and have the user use an iPhone HEIC photo for row 9. Can be done at merge time.
2. `tests/WheelConvert.Converters.Media.Tests/VideoSmallerTests.cs:184` — Comment says "short edge exactly 720 is untouched", but 720×406 has a short edge of 406. The exact-720 case (e.g. 1280×720) is not tested. **Fix:** correct the comment, or add `[InlineData(1280, 720, 1280, 720)]`.
3. `tests/WheelConvert.Converters.Image.Tests/ImageShrinkerTests.cs` — WebP quality 75 and PNG max compression are only checked indirectly (a big change makes the 5 % check fail; I7 and I8 above). A smaller drift (e.g. WebP q85) would likely pass. **Fix (follow-up):** assert the WebP output's `Quality` the way the JPEG test does.
4. `src/WheelConvert.Converters.Media/FfmpegArguments.cs:19` — Doc comment says the filter is "Proven against real FFmpeg in RealFfmpegTests"; the tests are in `VideoSmallerTests`. **Fix:** name the right class.
5. `docs/STATUS.md:22` — PR column says "branch wp-16-smaller"; other rows use "PR #NN". **Fix:** "PR #34" when the row is set to DONE.
