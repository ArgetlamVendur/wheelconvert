## Required findings

**R1. Removed pages lose their thumbnail after Reset (confirmed by running).**
`src/WheelConvert.App/Pdf/PageOrderViewModel.cs:91-99` and `src/WheelConvert.App/Pdf/PageOrderWindow.xaml.cs:57`.
Why: `Reset()` only reuses items still in `Pages`; a removed page gets a brand-new `PageItem` with no thumbnail. The loader walks a snapshot taken once at window load, so it never renders the new item (and if the page was removed before its turn, it renders into the orphaned old item). Result: remove page 2, press Reset, page 2 shows "Loading…" until the window is closed. The comment "Keeps already-loaded thumbnails" is wrong for exactly the pages Reset brings back.
Fix: keep every `PageItem` for the life of the view-model (for example a private array of all `_pageCount` items created once in the constructor, which `Reset` re-adds in order), and let the loader iterate that full set rather than a snapshot of `Pages`. Add a test: set a thumbnail, `Remove`, `Reset`, assert the same instance (with its thumbnail) is back.

**R2. Drag state goes stale if the list changes during a drag (read only, not reproduced).**
`src/WheelConvert.App/Pdf/PageOrderWindow.xaml.cs:89-113` (key handler) and `:170-176` (mouse move).
Why: the drag is tracked by position (`_dragIndex`), and `OnPreviewKeyDown` stays active while the mouse is captured. Pressing Delete (or Ctrl+Left/Right) while holding a page removes or moves it without updating `_dragIndex`. The next mouse move then drags a different page, or, when the last page was being dragged, `_viewModel.Pages[_dragIndex]` at line 172 throws `ArgumentOutOfRangeException`. The app-level handler turns that into a "Something went wrong" notification rather than a crash, but it is a real error path in the reentrancy area this WP is about.
Fix: track the dragged `PageItem` instead of an index and look its index up on each move (stop the drag if it is no longer in the list), or ignore Delete / Ctrl+arrows while `PageList.IsMouseCaptured`. Add a test for whichever guard is chosen.

**R3. Acceptance row 2 and the PR description state the wrong test count.**
`docs/modules/WP-09-pdf-reorder-window.md:26`, PR #16 description.
Why: both say "20 xUnit tests in `PageOrderTests`"; the file has 17 `[Fact]`s and the filtered run reports `Total: 17` (App suite 87 before, 104 now). The acceptance table must match what was run.
Fix: correct the number in the row and in the PR description (it will change again with the tests from R1, R2, R4).

**R4. Rules with logic that no test pins (AGENTS §2 reverted-fix rule).**
`tests/WheelConvert.App.Tests/PageOrderTests.cs`.
Why: mutations M9, M11, M12, M13 above leave all tests green. All four can be tested; the reviewer's scratch STA test did so with `new PageOrderWindow(vm, fakeRenderer, log, path)`, `Show()`, a short dispatcher pump and `Close()`.
Fix: add (a) `ProbeAsync` with a count of 0 returns "This file can't be read as a PDF."; (b) an STA window test that the renderer is called with indices 0..n-1 and 320; (c) closing the window cancels the token passed to the renderer and no further render is requested; (d) clicking Save with no pages leaves the window open and `FinalResult` null. Use the existing `RunInSta` pattern from `HotkeyParserTests.cs:175-199`, and close every window in a `finally`.

## Optional findings

**O1.** `PageOrderWindow.xaml.cs:69-72`: one page that fails to render stops loading for every later page (run: page 2 fails, pages 3 to 5 stay "Loading…"). Consider catching per page and continuing; pages that failed could show "No preview" rather than "Loading…".

**O2.** `PageOrderPrompt.cs:74-83`: the window and the message boxes have no owner and are never activated. Because the drop comes from Explorer, they may open behind the Explorer window. If the hand test shows this, call `Activate()` in the window's `Loaded` handler (no P/Invoke needed) and give the message box the same treatment.

**O3.** `PageOrderWindow.xaml:9`: the hint line is 126 characters; AGENTS §6 says user-facing text is at most 120. It wraps and is not a message, so it is listed here rather than as required; shortening it (for example dropping "Removed pages are left out of the new file.") settles it.

**O4.** `PageOrderWindow.xaml.cs:150-155`: if the left button is already up while the list still holds capture (a missed mouse-up), the handler returns without releasing; the next click anywhere in the window is swallowed. Release capture in that branch.

**O5.** `PageOrderWindow.xaml.cs:89-113` (read only): after Ctrl+Left/Right or Delete the item container is rebuilt, so keyboard focus may leave the list and plain arrow keys may stop moving the selection until Tab is pressed. If the hand test confirms it, focus the new container after the move.

**O6.** `PageOrderPrompt.cs:66-85`: the `cancellationToken` is ignored once the window is open (the only caller passes `CancellationToken.None`, so no effect today), and `Application.Current` is dereferenced without a null check. Note for a later WP, no change needed now.

**O7.** `tests/WheelConvert.App.Tests/PageOrderTests.cs` is not in the WP's Owns list. Tests are required by AGENTS §5 and nothing else was touched, so this is accepted; the Owns list should name the test file in future WPs.

**O8.** `PageOrderWindow.xaml.cs:60`: `Task.Run` around `RenderPagePngAsync` is redundant with the real renderer (it already runs off the caller's thread) but harmless and it protects against other implementations. `PageOrderPrompt.cs:8`: `PageProbe` is a second public type in the file; allowed by §6 as a small related type.

**O9.** Memory: thumbnails are decoded at their full 320 px though shown at about 170 px. 300 pages cost roughly 90 MB of pixels. Within the v1 limit; `DecodePixelWidth` would cut it if it ever matters.
