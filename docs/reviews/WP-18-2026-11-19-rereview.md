But `release.yml:115` resolves every `$notices` entry with `Join-Path $pk $n[0]`, where `$pk` is the NuGet cache (`release.yml:96`). A repo path there becomes `~/.nuget/packages/installer/licenses/…`, the `Test-Path` guard throws and the release build fails. It also leaves the user to choose names and folders. **Fix (author edits the PR description; exact steps for the user):**
   1. Open each link below in a browser, use the "Download raw file" button (or copy the text into a new file), and save it **without changing a byte** at the path shown:
      - <https://github.com/UglyToad/PdfPig/blob/a7bb35662bbbf405efddad50aedc9bcdcf515afc/LICENSE> → `installer/licenses/pdfpig/LICENSE.txt`

      - <https://github.com/dotnet/Open-XML-SDK/blob/3139fdfd27414548a41555f7848d5728f6e71a42/LICENSE> → `installer/licenses/open-xml-sdk/LICENSE.txt`
   2. Check each file is unchanged: in the repo folder run `git hash-object installer/licenses/pdfpig/LICENSE.txt` and so on. Expected (the git blob IDs upstream at those commits): PdfPig `LICENSE` `11b724b04fa8d6fd92298b2e4d3a0cba2b9eab0b`, PdfPig `NOTICES.txt` `b31cbe75835abeeeaa162ff1dd0508f7758212e5`, Open-XML-SDK `LICENSE` `12bd8f3f79693e49ff70d4ce182ff8d2e7baa390`. A different value means the file was altered (for example by a text editor); download it again. R3. **Non-blocking (new behaviour of the fix): paragraphs that are all one line, separated only by space-after, are merged into one paragraph.** `TextRules.cs:29-30`: when every pitch in a run is the same, the relative rule never fires, and the absolute rule needs > 2.5 × font size. Probe (11 pt, 13.2 leading, three paragraphs): one line each with 6 pt or 12 pt space after → **1 paragraph** (pitch 19.2 / 25.2 < 27.5). Three-line paragraphs with 6 or 8 pt after, and two-line ones with 12 pt after, correctly gave 3. The first version split these one-line cases. This is within req. 4's wording (one Docstrum block → one paragraph) and is less harmful than finding 2 was, but short one-line paragraphs (lists, addresses, one-sentence paragraphs) will run together. **Follow-up:** e.g. compare the pitch with the font size's normal leading (about 1.2 × size) as well as with the run median, and add the probe cases as tests.

R4. **Non-blocking: the relative-pitch rule is only unit-tested.** Removing `|| (pitchCount >= 2 && pitch > PitchJumpRatio * medianPitch)` fails only `StartsNewParagraph_Rules(26.4, 13.2, 3, 11)`. `TwoParagraphsSeparatedByABlankLine_AreTwoParagraphs` still passes, because its 39.6 pt gap also trips the absolute rule. **Fix (optional):** an end-to-end case where the paragraph gap is between 1.5 × median pitch and 2.5 × font size (e.g. 3-line paragraphs at 13.2 leading, gap 21 pt).

R5. **Nits (non-blocking), from first-review finding 9:** literal invisible U+FFFD/U+FFFE/U+FFFF/U+E000 characters remain at `TextRules.cs:109,124` and `DocxConverterTests.cs:142-143`; use `�`, `￾`, `￿`, ``. Not mentioned in the PR's fix list, so it should be added to Follow-ups. Also: the heading join (`PdfTextExtractor.cs:62-67`) will also join two different, closely stacked headings of the same level (e.g. "Chapter 1" over "Introduction" both at Heading 1). That's an acceptable trade-off for v1; mention it in "Decisions taken".
