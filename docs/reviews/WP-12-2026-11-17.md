## Required findings
**R1. installer/WheelConvert.iss:82: the .NET 8 Desktop Runtime check reads the wrong registry view, so Setup refuses to install on PCs that have the runtime.**
The script reads `HKLM64\SOFTWARE\dotnet\Setup\InstalledVersions\x64\sharedfx\Microsoft.WindowsDesktop.App`. On this PC (which has Desktop Runtime 8.0.34 in `C:\Program Files\dotnet\shared\Microsoft.WindowsDesktop.App\8.0.34`), I ran these read-only queries: `reg query "HKLM\SOFTWARE\dotnet\Setup\InstalledVersions\x64\sharedfx\Microsoft.WindowsDesktop.App" /reg:64` returns "unable to find the specified registry key", and the same query with `/reg:32` lists `7.0.20` and `8.0.34`. The .NET installer writes this key in the 32-bit view (`WOW6432Node`). `IsDesktopRuntime8Installed` therefore returns False, and `InitializeSetup` aborts on every PC. That fails acceptance test 2 and every winget install. Microsoft's page "Check installed .NET versions" (learn.microsoft.com/dotnet/core/install/how-to-detect-installed-versions, updated 2026-11-13) documents only the folder `C:\Program Files\dotnet\shared\{runtime-type}\{version}` and `dotnet --list-runtimes`, not this registry key.
Fix: check `HKLM32` (where the key actually is). Also accept `HKLM64` and/or a folder check of `{commonpf64}\dotnet\shared\Microsoft.WindowsDesktop.App\8.*` (`FindFirst`). Comment the source. For ARM64 (allowed by `x64compatible`), the folder under `{commonpf64}\dotnet` holds the arm64 runtime, so prefer the `InstalledVersions\x64` registry key in the 32-bit view and keep the folder check only as a fallback (or set `ArchitecturesAllowed=x64os`).

**R2. installer/WheelConvert.iss:24-47: no `AppMutex`, so upgrading or uninstalling while WheelConvert runs in the tray can leave the exe behind.**
The app holds the named mutex `Local\WheelConvert.SingleInstance` (src/WheelConvert.App/App.xaml.cs:16). `CloseApplications=yes` covers Setup only. Inno's CloseApplications page says nothing about the uninstaller. Restart Manager may not close a tray-only WPF app without force. A running exe can't be deleted, and a non-admin uninstaller can't schedule a delete at reboot, so acceptance test 3 ("program folder gone") fails whenever the app is running, which is the normal state. Inno's AppMutex page says "Setup and Uninstall" check it at startup and ask the user to close the app.
Fix: add `AppMutex=WheelConvert.SingleInstance`. A name without a prefix opens in the session's Local namespace. Confirm in the user's hand test (step 6 below).

**R3. THIRD-PARTY-NOTICES.md:61, :69, :108, :112: the FreeType and IJG credit lines are named as obligations, but the text the licences require is not written anywhere.**
The FTL text (Notice.txt line 2335; SkiaSharp THIRD-PARTY-NOTICES.txt line 726) asks for "Portions of this software are copyright © <year> The FreeType Project (www.freetype.org). All rights reserved." in the documentation. libjpeg-turbo's licence (SkiaSharp THIRD-PARTY-NOTICES.txt lines 1397-1405) says binary-only distributions "must include a message stating: This software is based in part on the work of the Independent JPEG Group." Both libraries ship in the exe (Magick.Native, libSkiaSharp and PDFium). These obligations are clear, not an open question.
Fix: add both sentences verbatim to THIRD-PARTY-NOTICES.md (and optionally the README Licence section). For `<year>`, use the year the source states, or list it as a question for the user if it is unclear.

## User hand-test list for Checkpoint 3 (after R1 and R2 are fixed and CI is green again)
Use a separate, clean Windows user account (Settings > Accounts > Other users > Add account), signed in as that user.
1. Download the `release-files` artifact from the PR's `release` run (or the draft release after your tag push). In PowerShell run `Get-FileHash .\WheelConvert-Setup-*.exe` and compare with `SHA256SUMS.txt`.
2. Right-click the Setup exe > "Scan with Microsoft Defender". Record the result in `docs/GO-NO-GO.md`.
3. Run the Setup exe. Expected: **no UAC/admin prompt**, no ".NET runtime missing" message (the runtime is installed on this PC), install folder `C:\Users\<user>\AppData\Local\Programs\WheelConvert`. Tick "Start with Windows" and "Start WheelConvert now".
4. Expected: tray icon appears. Shift-drag a scratch file from `wc-test` and drop it on a segment; output appears next to it. Watch for Defender/SmartScreen pop-ups in the first minutes. Then scan the installed `WheelConvert.exe` with Defender too.
5. `reg query HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v WheelConvert` shows `"C:\Users\<user>\AppData\Local\Programs\WheelConvert\WheelConvert.exe"`. Sign out and back in: the app starts.
6. **Leave the app running** and run the Setup exe again (upgrade). Expected: Setup asks you to close WheelConvert (R2), then completes.
7. **Leave the app running** and uninstall (Settings > Apps > WheelConvert > Uninstall). Expected: you're asked to close WheelConvert; then a question "Also delete your WheelConvert settings and log?" with **No** preselected. Answer No first time.
8. After uninstall: the folder `…\AppData\Local\Programs\WheelConvert` is gone, the Start-menu entry is gone, the `reg query` from step 5 says the value is not found, and `%LOCALAPPDATA%\WheelConvert\` still exists (because you said No).
9. Reinstall, then uninstall answering **Yes**: `%LOCALAPPDATA%\WheelConvert\` is gone. Nothing else in your profile changed. (`%TEMP%\.net\WheelConvert` may remain, see O10.)
10. Optional: on a PC or VM **without** the .NET 8 Desktop Runtime, Setup shows the "needs the .NET 8 Desktop Runtime" message and does not install.
11. VirusTotal: only if you choose to (uploading makes the file public); a SHA-256 lookup is the lower-exposure option. Record results in GO-NO-GO.md.
