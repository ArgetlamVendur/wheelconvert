## Findings (none blocking)
1. **`src/WheelConvert.Converters.Media/MediaConverter.cs:229`: possible partial-path leak after stderr truncation.** `MapFailure` (line ~301) drops ProcessRunner's `[…truncated…]` marker and the cut line after it, but `LogFailure` doesn't. The cut line starts mid-line, so if it held a path, `RedactPaths` can't match it and a fragment like `lex\Videos\clip.mov'` reaches the log. This is unlikely: FFmpeg prints the input path in its header, and that's the part a 64 KB tail drops first. **Fix:** in `LogFailure`, skip the marker line and the line after it, the same way `MapFailure` does.
2. **`tests/WheelConvert.Converters.Media.Tests/RealFfmpegTests.cs:40-52`: acceptance test 2 doesn't exercise the WP-21 fix.** With `-format_whitelist` removed, the test still passes. FFmpeg 9.0.2 refuses to probe HLS itself unless the file has a `.m3u8` extension (stderr: "Not detecting m3u8/hls with non standard extension"), and `clip.mp4` goes to `mov` → "moov atom not found" → `CorruptInput`. The "segment never read" check only scans the 20-line log. The defence is still real (`hls` is not whitelisted, and `-protocol_whitelist file` is set), and the ffconcat test (test 3) does fail when the whitelist is removed. **Fix (follow-up):** add a note in the acceptance table that test 2 passes on FFmpeg 9.0.2 even without the whitelist, or assert on a whitelist-specific outcome.
3. **`ImageConverter.cs:51`, `MediaConverter.cs:45`: three `FileLog` instances write to one file** (App, Image, Media), each with its own lock. `FileMode.Append` isn't atomic across handles, so concurrent jobs can interleave or lose log lines, and the 1 MB roll can race (the builder flagged the roll). This only affects the app's own log folder, which is exempt from C2, and it keeps the frozen `CompositionRoot` constructors unchanged (§4.1). **Fix (follow-up, needs an ADR):** pass the app's `ILog` into the converters.
4. **Protocol whitelist has no behavioural test, only the argument-list tests.** Removing `-protocol_whitelist file` makes 11 argument tests fail, but no real-FFmpeg test fails. That's expected: with the format whitelist in place, no allowed demuxer opens a nested URL by default (mov `enable_drefs` is off), so there's no input that can show the difference. Recorded as untestable behaviourally.

## Checklist
- Safety: no new file operations on user paths; output still goes only through `CreateTempPath`/`Commit`/`Discard` (unchanged). FFmpeg still runs only through `ProcessRunner` (the default ctor's delegate is unchanged; the test ctor is `internal`). No shell, no `UseShellExecute`. Untrusted stderr is logged as text only: `FileLog` turns line breaks into `⏎`, and lines are joined with ` | `, so stderr can't forge separate log lines.
