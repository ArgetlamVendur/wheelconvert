### 2.2 MSLLHOOKSTRUCT x64 Layout

The struct layout in `NativeMethods.Hook.cs` lines 38–55 is:
```csharp
[StructLayout(LayoutKind.Sequential)]
internal struct MSLLHOOKSTRUCT
{
    public POINT pt;          // offset 0, size 8
    public uint mouseData;    // offset 8, size 4
    public uint flags;        // offset 12, size 4
    public uint time;         // offset 16, size 4
    public nuint dwExtraInfo; // offset 24, size 8 on x64 (4 bytes padding at offset 20-23)
}
```
- Verified total size on x64 is 32 bytes (`Marshal.SizeOf<MSLLHOOKSTRUCT>() == 32`).
- Verified field offsets: `pt`: 0, `mouseData`: 8, `flags`: 12, `time`: 16, `dwExtraInfo`: 24.
- `PtXOffset` and `PtYOffset` in `ShiftDragTrigger.cs` (lines 20–24) use `Marshal.OffsetOf`, avoiding hardcoded numbers and matching native memory layout.

### 2.3 CallNextHookEx on Every Path (Including nCode < 0 and Exceptions)

In `ShiftDragTrigger.cs` lines 156–181:
- `if (nCode < 0)` immediately returns `CallNextHookEx` per Win32 specification.
- For `nCode >= 0`, processing occurs inside a `try { ... } catch (Exception) { ... } finally { result = CallNextHookEx(...); }` block.
- Any managed exception is caught so it cannot escape into native `user32` stack frames.
- `CallNextHookEx` is unconditionally invoked in `finally`, guaranteeing every message passes to the next hook and is never swallowed.

### 2.4 Delegate Lifetime (Kept in Field)

- `_proc` is stored in a private readonly field `private readonly NativeMethods.LowLevelMouseProc _proc;` (line 29), initialized in constructor `_proc = HookCallback;` (line 47).
- `TriggerManager` retains the `ShiftDragTrigger` instance in `_running` and `_shiftDrag` for its entire operational lifetime.
- The unmanaged function pointer obtained via `Marshal.GetFunctionPointerForDelegate(_proc)` points to a rooted delegate, preventing GC collection and premature callback invalidation.

### 2.5 Hook Callback Cost: No I/O, Logging, Locks, or Heavy Allocation

- **Early exit:** Normal mouse moves exit immediately at line 194 (`if (!_machine.IsWaitingForDrag) return;`) before doing any calculations, lookups, or P/Invokes. Over 99.9% of mouse traffic takes this fast exit.
- **Zero I/O and zero logging:** No file access, no console or logger calls, and no locks (`lock`, `Monitor`, `Semaphore`) anywhere in the callback path.
- **No heap allocations during drag:**
  - `_classNameBuffer` is a preallocated `char[64]` buffer reused across mouse-down checks.
  - Class name comparison uses `ReadOnlySpan<char>.Equals` with `StringComparison.OrdinalIgnoreCase`, allocating no `string` objects.
  - `ScreenPoint` and `GestureOutput` are stack-allocated `readonly record struct` value types.
  - Event handler delegates (`_raiseWheelRequested`, `_raiseWheelDismissRequested`) are preallocated and cached in constructor fields.

### 2.6 Hook Installed on the UI Thread

- `ShiftDragTrigger.Start()` calls `Dispatcher.FromThread(Thread.CurrentThread)` (line 86).
- If invoked from a background or non-dispatching thread, it returns `false` with `LastError = "Shift-drag could not start (not on the UI thread)."` rather than calling `Dispatcher.CurrentDispatcher` (which would create an orphaned dispatcher that never pumps).
- Hook callbacks are pumped through the WPF UI thread's message loop as required for `WH_MOUSE_LL`.

### 2.7 Stop and Dispose Idempotency

- `Stop()` (lines 125–137): checks `if (hook == 0) return;`. Clears `_hook = 0` before calling `UnhookWindowsHookEx`. Safe to call repeatedly or on an unstarted trigger. Return value is ignored per spec as Windows may have already unhooked a timed-out hook.
- `Dispose()` (lines 139–149): guards with `_disposed`, invokes `Stop()`, sets `_disposed = true`, and calls `GC.SuppressFinalize(this)`. Repeated `Dispose()` calls exit immediately.
- `Start()` on a disposed trigger returns `false` with `LastError = "Shift-drag has been shut down."`.

### 2.8 GestureStateMachine and Test Coverage

- `GestureStateMachine` is isolated, pure, and free of Win32 calls.
- `dragThresholdPx` uses squared comparison with `long` arithmetic to prevent 32-bit integer overflow on large multi-monitor virtual desktops.
- 9 unit tests in `tests/WheelConvert.App.Tests/GestureStateMachineTests.cs` thoroughly exercise:
  - Drag beyond threshold opens wheel at cursor point.
  - Drag without Shift does not open wheel.
  - Moves within threshold do not open wheel (including exact threshold boundary).
  - Fires exactly once per drag motion.
  - LeftDown not originating over Explorer/desktop does not arm.
  - LeftUp after firing outputs `Dismiss`.
  - LeftUp without firing outputs `None`.
  - Subsequent drag resets and fires cleanly from the new origin.
  - Shift pressed mid-drag opens wheel on the next move.
