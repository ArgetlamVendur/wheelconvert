# Review: WP-20 Smaller PDF (PR #32)

- **Reviewed head:** `ca50c6252c108d319fb685132d5a4b7e62f771ea` (branch `wp-20-pdf-smaller`)
- **Builder:** Sonnet. **Reviewer:** Opus, fresh session (no builder context).
- **Date:** 2026-11-19

## Verdict: **CHANGES NEEDED**

The file-safety design is correct and all safety lines pass. Two things block approval: one ADR-013 logging problem (folder paths and stack traces can reach the log) and several WP requirements that no test catches when they are reverted, although they could be tested.

## Findings

### Blocking

1. **`src/WheelConvert.Converters.Pdf/PdfShrinker.cs:90`: the render-check log line can contain full folder paths and a stack trace (ADR-013).**
   `log.Error(..., ex)` makes `FileLog` write `exception.ToString()` (type, message, full stack, inner exceptions). The render check opens temp B with `new FileStream(tempB, ...)` (`Pdfium.cs:88-89`), so an `IOException` there (for example antivirus holding the new file) has a message like `The process cannot access the file 'D:\Users\<name>\Documents\...\.wctmp-<guid>.pdf'`, with the user's folder and Windows user name in it. ADR-013 says a shared log must not reveal folder names. The other converters log only `Type: message`, with the paths reduced to file names and the text cut short (`ImageConverter.cs:253-259`, `MediaConverter.RedactPaths`).
   **Fix:** log `$"Smaller PDF failed for {Path.GetFileName(source)}: {ex.GetType().Name}: {redacted message}"`, with temp B and the source path replaced by their file names, cut to 500 characters like ImageConverter, and with no exception object (so no stack trace). Add a test whose render-check delegate throws an `IOException` that contains the temp path, and assert that the logged text has no directory part.

2. **Required rules that a test could catch but none does.** In a scratch run I reverted each rule on its own and ran the Pdf tests (91 tests). All tests still **passed** for these:
   - **Quality 70** (`PdfShrinker.cs:21`): changing it to 90 → all pass. Suggested test: re-encode a known image and check that the output JPEG's quantisation matches quality 70, or that the output is smaller than a re-encode at 90 by a clear margin.
   - **Replace only if smaller** (`PdfShrinker.cs:281`): removing the check → all pass. Suggested test: an image that is already a quality-40 JPEG under 2000 px stays byte-identical.
   - **Content-stream compression** (`PdfShrinker.cs:69`, req. 4): removing it → all pass. Suggested test: a page with an uncompressed content stream comes out with `/Filter /FlateDecode`.
   - **Cancellation between images** (`PdfShrinker.cs:179`, req. 6): removing `ThrowIfCancellationRequested` → the cancel test still passes, because the cancelled token is noticed later (in the render check or Pdfium). The test doesn't prove the loop stops between images. Suggested test: cancel at the first progress report and assert that the image pass stopped (for example `LastStats` is null or no Save happened), or use a counting render-check delegate that must not be called.
   - **DCTDecode only / 8 bits only** (`PdfShrinker.cs:213`): removing either check → all pass. The JPEG-header check (`JpegInfo`) is a second guard, so this isn't a live bug, but req. 3's "skip everything else" has no test. Suggested test: a Flate-encoded RGB image and a 16-bit image are counted as skipped and left unchanged.
   - **Never enlarge** (`PdfShrinker.cs:262`): `if (true)` → all pass, because the "replace only if smaller" check happens to throw away the enlarged image. Covered once item 2b has a test. Otherwise add a test with a small image whose re-encode is smaller.

   Agent acceptance rows 1-7 are marked PASS and the rows themselves are covered. These are requirement lines (req. 3, 4, 6) that AGENTS.md §2 asks to prove with a failing reverted test, or to explain why they can't be tested.

### Non-blocking

3. **`PdfShrinker.cs:98`: source-side I/O errors are reported as "Couldn't save the file here."** The outer `catch (IOException or UnauthorizedAccessException or InvalidOperationException)` → `OutputFailed` also catches `FileNotFoundException` from `new FileInfo(source).Length`/open (source deleted after the `File.Exists` check) and a sharing violation on the source. So these never reach `PdfConverter`'s own `SourceMissing` / "Another app may be using it" mappings. `InvalidOperationException` thrown by PDFsharp's `Save` for a malformed structure would also show the "save" message. Suggestion: split the catch, or let source-side exceptions reach `PdfConverter`.
4. **`PdfShrinker.cs:48,70`: `FileMode.Create` on temp A and temp B.** Both paths come from `IOutputWriter.CreateTempPath`, so the checklist allows this and it is not a safety finding. `FileMode.CreateNew` (as `Pdfium.SavePagePngAsync` uses) would fail loudly instead of truncating if a temp name were ever reused. That would be a cheap hardening.
5. **Two rules are covered by reading only, because no file-level test can tell the difference (they cannot be tested):**
   - "Never open the source in Modify mode" (req. 2, S1): changing `OpenForEdit(tempA)` to `OpenForEdit(request.SourcePath)` → all tests pass. PDFsharp's `PdfReader.Open` reads the file into memory and never writes it back, so the source hash stays the same either way. I checked by reading that only temp A is opened in Modify mode.
   - `/Length` update (`PdfShrinker.cs:296`): removing it → all pass, because PDFsharp rewrites `/Length` on save. The test assertion `Length == Stream.Length` is still useful.
6. **Mask-of-another-image exclusion** (`PdfShrinker.cs:181`): setting `isMask = false` → all pass. The test's 1×1 mask isn't a JPEG, so the other checks skip it anyway. A test with a DCT-encoded `/SMask` target would cover it.
7. **`PdfShrinker.cs:135-136`: two blank lines in a row in `OpenForEdit`.** Cosmetic.
8. **App tests: the first `dotnet test tests/WheelConvert.App.Tests -c Release` run aborted ("Test host process crashed").** An immediate rerun with `--no-build` passed 118/118. This PR doesn't touch App, so it is likely an existing flaky test and is recorded only for follow-up.
