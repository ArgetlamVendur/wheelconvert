## Findings

1. **Minor (scope) — `tests/WheelConvert.Converters.Pdf.Tests/PdfConverterTests.cs:396-398`** is outside the WP's Owns list.
   Why: AGENTS §2.4. The change is needed, though: adding three PDF targets to `TargetCatalog.All` breaks `Supports_AllPdfTargets_OnlyForPdf` (it compares the catalog with what the Pdf converter supports), so CI would be red without it. The WP spec missed this; the builder disclosed it in the PR description (§4.12) and changed only the test, not the converter.
   Fix: none needed in this PR. User/orchestrator: please acknowledge the exception. WP-14/18/20 must remove their ID from `notYet` (the comment says so).

2. **Minor (docs, frozen contract) — `docs/CONTRACTS.md:53`** reference pattern now reads `var ext = request.Target.OutputExtension ?? ".png";`.
   Why: the line right above (C1 row, and ADR-011 §4) says a null extension means "the converter chooses, normally the source's own". A builder copying the reference pattern for `image.smaller`/`image.resize` would turn `photo.jpg` into `photo (smaller).png`. The pattern should not suggest a hard-coded fallback.
   Fix (one line, docs only): `var ext = request.Target.OutputExtension ?? FileClassifier.NormalizeExtension(request.SourcePath); // null = keep the source's format (ADR-011 s4)`, or the `is not { } ext` → `Fail(Unsupported)` form the converters already use. Can be done at the rebase onto `main` or in WP-16; not worth another review round on its own.

3. **Note — `src/WheelConvert.App/Composition/DropCoordinator.cs:74-92`**: the `RequiresInteraction` branch still assumes a PDF and ignores `_resizePrompt`. Safe today (no converter lists `image.resize`, so the segment is hidden and the planner would skip it with "No converter available"). The PR records it as a WP-19 follow-up; WP-19 must add the resize branch before any converter lists `image.resize`.

4. **Note — `src/WheelConvert.Core/Contracts/ConversionTarget.cs:40-46`**: `MinInputs`/`MaxInputs` are redeclared as get-only properties so they are validated. Side effect: `target with { MinInputs = … }` does not compile (copying with `with` for other properties still works and keeps the validated values). No code uses `with` on targets; acceptable, and it is within ADR-011 §1 and WP req. 1.
